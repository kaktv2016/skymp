## Navigation lifecycle / persistence

Navigation and completion metadata extend existing owner-only rpChatInboxV1; isVisibleByNeighbors stays false. Active route derives from existing native Courier state and configured destination; unknown/invalid/idle state publishes null. Server refresh is once per second and on chat replies, only writing changed metadata. No new financial store/schema, migrations or journal reads occur during ambient refresh. G1.1 reconciliation remains in its original economic command paths; if a native mirror is temporarily stale during an ambiguous storage failure, the visual hint may remain stale until an existing economic command reconciles it. It cannot authorize delivery/payment.

Client creates at most one local temporary reference, initially disabled with forcePersist=false, positions/rotates/scales it, then enables after validity checks. No server object creation or networked activation is added. Generation checks cancel late placement after finish/abandon/unload/actor change. A pending placement or deletion prevents another spawn. Failed deletion retries after two seconds, including after disposal; replacement controllers await old cleanup. Only owned handles/reference are removed.

Updates are bounded to twice per second. Loading/Main menus, unloaded player, another cell/world or a destination beyond 8192 units suppress the beacon; return to the relevant loaded area restores it. Exterior cells in the same world are supported, with recreation on parent-cell change. Reconnect requires fresh active owner state; loadGame retires references while retaining a still-active target. No door/pathfinding routing or far-LOD beam beyond loaded-area rendering is claimed. Existing route is approximately 1169 units long, within this range. No permanent quest/ESP, custom shader, art asset, NPC, new economy feature or launcher/modpack work.
